# 발렛 유형과 시나리오

발렛 한 번(맡김 ~ 찾음)을 처음부터 끝까지 따라가며, 고객 · 요원 · 시스템이 각각 무엇을 하는지 정리합니다.
규칙의 근거는 [valet-session.md](valet-session.md), 화면은 [screens.md](../design/screens.md), 미정 사항은 [open-questions.md](open-questions.md) 를 봅니다.

## 유형 나누는 기준

발렛의 흐름은 세 가지에 따라 달라집니다.

| 기준 | 값 | 무엇이 달라지나 |
|---|---|---|
| 고객 | 회원 / 비회원 | 앱 사용, 알림, 자동 연결 |
| 오는 방식 | 도착 알림을 보내고 옴 / 그냥 옴 | 세션이 언제 생기나, 업체를 아나 |
| 부스의 계약 업체 수 | 1곳 / 2곳 이상 | 주차할 때 업체 · 티켓을 정할 수 있나 |

비회원은 앱이 없어 도착 알림을 보낼 수 없습니다.

## 유형

| 유형 | 고객 | 오는 방식 | 계약 업체 | 업체 · 티켓이 정해지는 때 |
|---|---|---|---|---|
| **A. 예약형** | 회원 | 도착 알림 | 상관없음 | 도착 알림 때 (고객이 고른 업체) |
| **B. 현장형 (업체 1곳)** | 회원 | 그냥 옴 | 1곳 | 주차할 때 자동 |
| **C. 현장형 (업체 여러 곳)** | 회원 | 그냥 옴 | 2곳 이상 | 정해지지 않음 ⚠️ (업체 QR 을 찍으면 그때) |
| **D. 비회원** | 비회원 | 그냥 옴 | 1곳 / 2곳 이상 | 1곳이면 주차할 때 자동, 아니면 출차 요청할 때 업체 QR 로 |

모든 유형에서 공통으로 **출차 요청은 업체를 몰라도 됩니다.** 출차 요청은 부스로 가고, 요금 기준표와 계좌도 부스 것입니다.

---

## A. 예약형 — 회원이 도착 알림을 보내고 옴

> 예: 회원이 그랜드 하얏트 서울 저녁 약속에 가면서 미리 도착 알림을 보냄

| # | 누가 | 무엇을 | 시스템 |
|---|---|---|---|
| 1 | 고객 | 앱 메인 → **업체 검색** → "그랜드 하얏트 서울" 선택 | |
| 2 | 고객 | **도착 알림 보내기** | 세션 생성: **도착 예정**, 업체 = 그랜드 하얏트, 부스 = 아직 모름 |
| 3 | 시스템 | 그 업체와 계약한 **모든 부스의 요원**에게 알림 | 근무 시간 밖이라 알림이 꺼진 요원은 받지 않음 (Figma 요원 12~13번 기준) |
| 3-1 | 고객 | (늦어지면) **지연 알림** — 5분 / 10분 / 15분+ | 세션에 지연 시간 기록 (상태는 그대로) |
| 3-2 | 고객 | (안 가게 되면) **도착 알림 취소** | 상태 → **취소**. 끝 |
| 4 | 요원 | 도착한 차를 받아 주차 → 앱 목록에서 그 차를 **눌러 주차 처리** | 상태 → **주차 완료**, 주차 시각(요금 시작), 처리한 요원, 부스 = 그 요원의 부스, **업체의 최신 티켓** 연결 |
| 5 | 고객 | 앱 메인에서 "주차 완료", 경과 시간, 지금 출차 시 요금 확인. **발렛 티켓** 보기 | 고객에게 주차 완료 알림 |
| 6 | 고객 | **출차 요청** → 요금 계산 내역 확인 → 접수 | 상태 → **출차 요청**, 출차 요청 시각(요금 끝), **기준 요금** 계산 · 고정 |
| 7 | 요원 | **출차 응답** — 실제 요금, 예상 출차 시각 입력 | 상태 → **출차 준비 중**, **실제 요금** 고정(이후 수정 불가) |
| 8 | 고객 | **알럿**으로 실제 요금 · 예상 시각 확인, 부스 **계좌번호 복사** → 계좌이체 | |
| 9 | 요원 | 차를 건넴 → **출차 완료** | 상태 → **출차 완료**, 처리한 요원 기록 |
| 10 | 사람 | 입금 확인 (시스템 기능 없음) | |

**요금 예시**: 19:00 주차 완료 → 20:10 출차 요청 = 1시간 10분 → 기준 요금 **17,000원**. 요원이 15,000원으로 응답하면 고객이 낼 금액은 **15,000원**.

## B. 현장형 (업체 1곳) — 회원이 알림 없이 옴

> 예: 회원이 계약 업체가 한 곳뿐인 식당 앞 부스에 그냥 차를 맡김

| # | 누가 | 무엇을 | 시스템 |
|---|---|---|---|
| 1 | 고객 | 요원에게 차를 맡김 | (아직 세션 없음) |
| 1-1 | 고객 | (이때 앱에서 출차 요청을 누르면) "요원님께서 주차 중입니다" 안내 | 진행 중 세션이 없어서 |
| 2 | 요원 | 주차 후 앱에서 **차량 추가** → 차량 번호 입력 | 세션 생성: **주차 완료**, 주차 시각, 처리한 요원, 부스. 같은 번호의 진행 중 세션이 있으면 거부(입력 실수) |
| 3 | 시스템 | 그 번호로 가입한 회원을 찾아 **자동 연결** | 부스의 계약 업체가 1곳 → **업체 · 최신 티켓 자동 연결** |
| 4~ | | A 의 5 ~ 10 과 같음 | |

## C. 현장형 (업체 여러 곳) — 회원이 알림 없이 옴 ⚠️

> 예: 백화점 · 식당 여러 곳과 계약한 부스에 회원이 그냥 차를 맡김

| # | 누가 | 무엇을 | 시스템 |
|---|---|---|---|
| 1~2 | | B 의 1 ~ 2 와 같음 | |
| 3 | 시스템 | 회원 자동 연결 | 계약 업체가 2곳 이상 → **업체 · 티켓을 정하지 않음** |
| 4 | 고객 | 앱 메인에서 주차 완료 확인. **발렛 티켓은 없음** ("현재 발급받은 발렛티켓이 없습니다") | |
| 4-1 | 고객 | (선택) 업체에 붙은 **QR 을 찍고 차량 번호 입력** | 그 업체가 세션의 부스와 계약된 곳이면 **업체 · 최신 티켓 연결** |
| 5~ | | A 의 6 ~ 10 과 같음 (출차 요청은 업체 없이도 됨) | |

허점으로 알고 둔 유형입니다. → [open-questions.md](open-questions.md)

## D. 비회원 — 앱 없이 옴

> 예: 앱이 없는 고객이 차를 맡기고, 나갈 때 업체 테이블의 QR 로 출차 요청

| # | 누가 | 무엇을 | 시스템 |
|---|---|---|---|
| 1 | 고객 | 요원에게 차를 맡김 | |
| 2 | 요원 | 주차 후 **차량 추가** → 차량 번호 입력 | 세션 생성: **주차 완료**, 회원 연결 없음. 계약 업체 1곳이면 업체 · 티켓 자동 연결 |
| 3 | 고객 | 나갈 때 업체에 붙은 **QR 촬영** → 브라우저 | 차량 번호 입력 전: **그 업체의 최신 티켓** |
| 4 | 고객 | **출차 요청** → **차량 번호 입력** | 그 번호의 진행 중 세션을 찾음. 업체가 없었으면 **이 업체로 연결 + 최신 티켓**. 상태 → **출차 요청**, 기준 요금 고정. 이후 세션의 티켓을 보여줌 |
| 5 | 요원 | **출차 응답** — 실제 요금, 예상 시각 | 상태 → **출차 준비 중** |
| 6 | 고객 | 실제 요금 확인 ⚠️, 계좌번호 복사 → 이체 | 비회원은 전화번호가 없어 푸시 · 알림톡을 보낼 수 없음 |
| 7 | 요원 | **출차 완료** | |

⚠️ 비회원에게 실제 요금을 어떻게 알릴지(QR 로 연 화면에서만 보여줄지 등)는 미정입니다. → [open-questions.md](open-questions.md)

## 공통 예외

| 상황 | 처리 |
|---|---|
| 도착 알림 후 오지 않음 | 도착 예정으로 계속 남음 (자동 만료 없음) |
| 요원이 같은 차량 번호를 두 번 입력 | 진행 중 세션이 있으면 **입력 실수로 거부** |
| 도착 알림을 보낸 차를 요원이 번호로 또 추가 | 위와 같이 거부. 도착 예정 차는 **목록에서 골라** 처리 |
| 출차 요청 후 취소 | 기능 없음 |
| 실제 요금에 고객이 동의하지 않음 | 시스템 단계 없음 (현장 해결) |
| 주차 완료 전에 출차 요청 | "아직 주차 완료되지 않은 차량입니다" |
| 입금 확인 | 시스템 기능 없음, 사람이 확인 |
