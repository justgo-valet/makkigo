# 정책

## 결제

- 1차 MVP 는 **PG 연동 없음**. 고객이 직접 계좌이체합니다.
- 앱은 **부스가 설정한 계좌번호를 보여주고 복사**하게만 합니다.
- **입금 확인 기능은 없습니다.** 사람이 직접 확인합니다. (그래서 시스템은 "결제 완료" 상태를 알 수 없습니다)
- 요금 규칙 → [valet-session.md](valet-session.md#요금)

## 약관 동의

**위치**: 소셜 로그인 직후, 온보딩 첫 단계.
개인정보(휴대폰·차량 번호)는 받기 **전에** 동의를 받아야 하고, 로그인 전에는 기록할 회원이 없어서 이 위치입니다.

| 항목 | 구분 |
|---|---|
| 만 14세 이상 확인 | 필수 |
| 서비스 이용약관 | 필수 |
| 개인정보 수집 · 이용 | 필수 |
| 개인정보 제3자 제공 (발렛 부스) | 필수 |
| 앱 푸시 | 선택 |
| 알림톡 | 선택 |
| 위치기반서비스 이용약관 (개인위치정보 수집 · 이용) | 선택 |

- 동의 상태를 덮어쓰지 않고 **이력으로 쌓습니다.** 항목별 가장 최근 기록이 현재 상태입니다.
- 동의한 **약관 버전**(시행일)을 함께 기록합니다.
- 국외 이전(FCM · APNs)은 동의 항목이 아니라 **개인정보 처리방침에 공개**합니다 (제28조의8 제1항 제3호). 데이터는 AWS 서울 리전에 저장합니다.
- 만 14세 미만은 보호자 동의 절차가 필요해서 가입을 받지 않습니다 (제22조의2).
- 약관 본문 초안과 검토할 점 → [legal/README.md](../legal/README.md)
- 필수 항목을 철회하는 것은 사실상 탈퇴이므로 미동의로 보낼 수 없습니다.
- 선택 항목은 마이페이지에서 언제든 동의 · 철회합니다. 앱 푸시를 철회하면 그 회원의 기기 토큰을 모두 지웁니다 (다시 동의하면 앱이 다시 등록).
- 필수 동의가 없으면 온보딩을 저장할 수 없습니다.
- 소셜 로그인만 하고 필수 동의 없이 **30일**이 지난 회원은 소셜 계정 정보를 지웁니다 (2026-10-16 결정). 정기 작업에 추가하는 일은 남아 있음 → [legal/README.md](../legal/README.md#2026-10-16-검토-뒤-남은-할-일)
- 소셜 계정 식별자 · 이메일의 처리 근거는 동의가 아니라 **계약 체결 · 이행**입니다. 소셜 로그인 콜백에서 먼저 저장되기 때문입니다.

## 위치정보

도착 알림을 보낼 때 현재 위치로 업체까지 **자동차 예상 도착 시각**을 계산해 요원 화면에 보여줍니다.

- 동의: 온보딩 약관 단계의 **선택** 항목. 거기서 동의하지 않았으면 **도착 알림을 보낼 때마다** 위치 동의를 묻고, "동의 안 하고 보내기"도 둡니다.
- 위치는 "보내기"를 누를 때 **한 번만** 받습니다. 오는 동안 다시 계산하지 않습니다 (백그라운드 위치 수집 없음).
- 동의 안 함 · OS 위치 권한 거부 · 위치 조회 실패 · 업체 주소로 좌표를 못 찾음 · 길찾기 실패면 도착 알림은 그대로 보내고 예상 시각은 **미정**입니다.
- 좌표는 계산에만 쓰고 저장하지 않습니다. 이용 사실(누가 · 언제 · 무엇에)만 기록합니다 → [legal/README.md](../legal/README.md#위치정보)
- 위치는 **앱에서만** 받습니다(서비스는 앱으로만 제공). 앱 밖 브라우저로 열면 미정으로 보냅니다.

## 알림

고객에게 보내는 알림(주차 완료, 출차 응답 등)은 **앱 푸시가 먼저, 안 되면 알림톡**으로 보냅니다.

| 상황 | 보내는 방법 |
|---|---|
| 앱 푸시 동의 + 기기 토큰 있음 | 앱 푸시 |
| 앱 푸시 미동의, 기기 토큰 없음, 또는 **푸시 발송 실패** | 알림톡 |

- "발송 실패"는 FCM 이 오류를 돌려준 경우(토큰 만료 · 앱 삭제 등)입니다. FCM 은 기기에 실제로 표시됐는지는 알려주지 않으므로, 발송에 성공한 푸시는 도착한 것으로 봅니다.
- 앱 푸시와 알림톡 모두 미동의인 경우는 [open-questions.md](open-questions.md).
- **알림톡 발송은 아직 연동되지 않았습니다.** 지금은 푸시를 못 보내면 알림 내역에만 남습니다 → [open-questions.md](open-questions.md)
- 실제로 보낸 경로는 알림 내역(`notifications.channel`)에 기록합니다. "알림을 못 받았다"는 문의에 어느 경로로 갔는지 확인하기 위해서입니다.

## 회원 정보

- 휴대폰 번호는 **회원끼리 중복 불가**. 숫자만 저장 (`01012345678`).
- 차량 번호는 **회원 1명만** 등록 (1차 MVP). 공백·하이픈 제거, 신형 번호판(`12가3456`, `123가4567`)만 허용.
- 회원 1명당 차량 1대 (1차 MVP).

## 로그아웃

**이 기기만** 로그아웃합니다. 다른 기기의 로그인은 유지됩니다.

## 회원 탈퇴

| 대상 | 처리 |
|---|---|
| 소셜 연결 | **즉시 삭제** — 같은 소셜 계정으로 다시 가입 가능. 애플은 애플에도 연결 해제(토큰 철회)를 요청 |
| 로그인 | **모든 기기** 즉시 로그아웃 |
| 휴대폰 번호 · 차량 | **30일 보관 후 삭제** — 분쟁 대응. 보관 기간에는 같은 번호로 재가입 불가 |
| 약관 동의 이력 | 보존 |
| 지난 발렛 기록 | 세션에 차량 번호가 따로 남음 |

- **진행 중인 발렛**(도착 예정 · 주차 완료 · 출차 요청 · 출차 준비 중)이 있으면 탈퇴할 수 없습니다. 도착 예정이면 도착 알림을 취소하고, 맡긴 차는 출차 완료 후 탈퇴합니다. 탈퇴하면 주차 완료 · 출차 응답 알림을 받을 사람과 출차 요청할 수단이 사라지기 때문입니다.
- 실제 삭제는 한 시간마다 도는 정기 작업이 합니다 → [runbook.md](../operations/runbook.md#정기-정리-작업)
- 애플 토큰 철회가 실패해도 탈퇴는 진행합니다(서버 로그만 남김). 이 기능 전에 로그인한 애플 회원은 저장된 토큰이 없어 철회하지 못하므로, 다시 로그인하면 토큰이 저장됩니다.

검토했던 다른 방식: 탈퇴 즉시 번호 비우기(A), 번호 일부만 가려 보관(B). 분쟁 대응을 위해 기간 보관(C)을 택했습니다.
