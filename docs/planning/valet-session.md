# 발렛 세션

한 번의 맡김~찾음이 세션 하나입니다. 같은 차가 하루에 두 번 오면 세션도 두 개입니다.
유형별로 처음부터 끝까지 따라가는 예시는 [valet-scenarios.md](valet-scenarios.md) 를 봅니다.
테이블: `valet_sessions` (#9) → [database.md](../architecture/database.md)

## 상태

```
 [도착 예정] ──(고객이 도착 알림 취소)──▶ [취소]
     │ 요원이 목록에서 눌러 주차 처리
     ▼
 [주차 완료] ◀── 도착 알림 없이 온 차: 요원이 주차 후 차량 번호 입력
     │ 고객 출차 요청 → 기준 요금 확정
     ▼
 [출차 요청]
     │ 요원 출차 응답 → 실제 요금 · 예상 출차 시각, 고객 알럿
     ▼
 [출차 준비 중]
     │ 요원 출차 완료
     ▼
 [출차 완료]
```

| 상태 | enum |
|---|---|
| 도착 예정 | `ARRIVING` |
| 주차 완료 | `PARKED` |
| 출차 요청 | `PICKUP_REQUESTED` |
| 출차 준비 중 | `PICKUP_PREPARING` |
| 출차 완료 | `COMPLETED` |
| 취소 | `CANCELLED` |

- **"주차 중" 상태는 없습니다.** 인수 버튼이 없어서 맡긴 시점을 기록할 수 없습니다.
- **지연은 상태가 아니라 속성**입니다 (도착 예정 세션의 지연 시간). 상태로 만들면 지연이 끝났을 때 돌아갈 곳이 모호해집니다.
- 도착 알림 후 고객이 오지 않으면 **도착 예정에 그대로** 둡니다 (MVP 범위 밖).
- 출차 요청 취소, 실제 요금에 대한 고객 동의 단계는 없습니다.
- 상태 변경 이력 테이블은 두지 않고, 처리한 요원을 세션에 기록합니다 (주차 · 출차 응답 · 출차 완료).

## 세션이 생기는 경로

1. 회원이 **도착 알림**을 보냄 → 도착 예정 (업체는 선택됨, 부스는 아직 모름)
2. 알림 없이 온 차를 요원이 **주차 후 번호 입력** → 주차 완료

## 도착 알림

- 받는 요원: 그 업체와 **승인된 계약**을 맺은 부스(삭제 안 됨)에 **승인된** 요원 중 알림이 켜진 사람. 여러 부스에 속한 요원도 한 번만 받습니다.
- 승인된 계약 부스가 하나도 없는 업체면 **거부**합니다. 받을 사람이 없는 세션을 만들지 않습니다.
- 알림이 켜진 요원이 지금 한 명도 없어도 세션은 만듭니다 (요원 앱 목록에는 보임).
- 티켓은 이때 붙이지 않고 **주차 처리할 때** 붙입니다 ([시나리오 A](valet-scenarios.md#a-예약형--회원이-도착-알림을-보내고-옴) 4번).
- 지금은 요원별 알림 내역(`notifications`, 채널 비움)만 남깁니다. 실제 푸시(FCM) 발송은 알림 발송 작업에서 붙입니다.
- **취소**는 도착 예정일 때만 됩니다. 요원이 주차 처리를 시작한 뒤(주차 완료 이후)에는 거부합니다. 취소 알림은 **처음 도착 알림을 받았던 요원**에게만 갑니다. 그 뒤 근무를 시작한 요원은 목록에서 사라지는 것으로 압니다.

## 중복과 회원 자동 연결

- 도착 예정 차는 요원이 **목록에서 골라** 처리합니다. 번호를 다시 입력하지 않습니다.
- 번호 직접 입력은 알림 없이 온 차 전용입니다. 같은 번호로 **진행 중인 세션**(출차 완료·취소가 아닌 것)이 있으면 요원의 입력 실수로 보고 거부합니다. 지난 세션은 상관없습니다.
- 도착 알림도 같은 번호로 진행 중인 세션이 있으면 거부합니다.
- 요원이 입력한 번호로 가입한 회원이 있으면 **자동으로 연결**합니다. 차량 번호는 회원 1명만 등록할 수 있어 대상이 하나로 정해집니다.
- 차량 번호는 공백·하이픈을 뺀 형태로 비교합니다 (`12가3456`).

## 업체 연결

| 상황 | 업체 |
|---|---|
| 도착 알림 | 고객이 고른 업체 |
| 부스에 계약 업체가 1곳 | 주차할 때 그 업체로 자동 연결 |
| 부스에 계약 업체가 2곳 이상 + 알림 없이 온 차 | **연결 안 함** (허점) → [open-questions.md](open-questions.md) |
| 업체 QR 로 차량 번호 입력 (비회원, 또는 회원 번호여도) | 그때 연결 |

업체가 없어도 **출차 요청은 됩니다.** 출차 요청은 부스로 가고, 요금 기준표와 계좌도 부스 것입니다. 업체가 없으면 티켓만 못 보여줍니다.

## 티켓

- 업체가 디자인을 바꿔도 **이미 발급된 티켓은 그대로**입니다. 수정할 때마다 새 버전을 만들고, 세션은 발급 당시 버전을 가리킵니다.
- 세션에 업체가 정해지는 순간 **그 업체의 최신 티켓**(가장 최근에 만들거나 수정한 버전)이 붙습니다.
- 비회원이 QR 로 들어와 번호를 입력하기 전에는 업체의 최신 티켓을, 입력한 뒤에는 세션의 티켓을 보여줍니다.
- 홍보 문구는 티켓 디자인에 포함됩니다.

## 요금

| | 기준 요금 (`base_fee`) | 실제 요금 (`actual_fee`) |
|---|---|---|
| 정하는 사람 | 시스템 (부스 요금 기준표) | 요원 (재량) |
| 정해지는 때 | 고객이 **출차 요청**한 순간 | 요원이 **출차 응답**할 때 |
| 고객에게 | 출차 요청 화면의 요금 계산 내역 | 알럿으로 안내, 최종 요금 |
| 수정 | — | **불가** |

요원이 현장에서 기준표대로 엄격히 받지 않고 융통성 있게 받는 업계 관행 때문에 두 금액을 나눴습니다.

**기준표** (부스별 설정, 기본값은 Figma 요원 5번 화면)

```
기본 1시간 12,000원 + 초과 30분마다 5,000원 (30분 미만은 올림)
이용 시간 = 주차 완료 시각 ~ 출차 요청 시각

1시간     → 12,000원
1시간 1분 → 17,000원
1시간 10분 → 17,000원
```
