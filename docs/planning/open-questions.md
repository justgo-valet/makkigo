# 미정 · 허점 목록

정해지면 해당 문서와 [decisions.md](../decisions.md) 에 옮기고 여기서 지웁니다.

## 기획

| 항목 | 현재 상태 | 영향 |
|---|---|---|
| 계약 업체가 2곳 이상인 부스에, 도착 알림 없이 온 **회원** | 업체를 알 수 없어 티켓 없음. 그대로 둠 | 티켓만 못 봄 (출차 요청은 됨) |
| 도착 알림 후 고객이 오지 않음 | 도착 예정 상태로 계속 남음 | 요원 목록에 쌓임 |
| 출차 요청 취소 | 기능 없음 | |
| 출차 응답 알럿 화면 | 디자인 없음 | 실제 요금 안내 |
| 비회원에게 실제 요금 · 출차 준비 알리기 | 전화번호가 없어 푸시 · 알림톡 불가. QR 로 연 화면에서만 보여줄지 미정 | 비회원 출차 ([시나리오 D](valet-scenarios.md#d-비회원--앱-없이-옴)) |
| 약관 확정 | 초안. 회사명 · 보호책임자 · 알림톡 대행사 빈칸, 변호사 검토 → [legal/README.md](../legal/README.md) | 동의 화면 · 처리방침 |
| 위치기반서비스사업 신고 · 위치정보관리책임자 | 회사가 진행. 신고 처리 기간 확인 필요 → [legal/README.md](../legal/README.md#위치정보) | 위치 동의 · 예상 도착 시각 출시 |
| 개인정보 처리방침 공개 페이지 | 초안만 있음. 스토어 등록에 공개 주소 필요 | 스토어 출시 |
| 티켓 디자인 저장 형식 | JSON 컬럼 자리만 둠 | 티켓 편집기 구조가 정해져야 함 |
| 앱 푸시 · 알림톡 **둘 다 미동의**한 회원 | 알림을 보내지 않고 앱 화면에서만 보여줄지 미정 | 주차 완료 · 출차 응답 안내 |

## 개발

| 항목 | 현재 상태 |
|---|---|
| 배포 Actions · AWS 준비 | 방식은 결정됨 (GitHub Actions + GHCR, OIDC + SSM 명령 실행, 도메인 · Caddy). 워크플로와 AWS 설정이 남음 → [deployment.md](../architecture/deployment.md#진행-상황) |
| DB 백업 | DB 가 서버 안 컨테이너라 백업(정기 덤프 → S3 등)을 직접 해야 함 |
| 만료 · 폐기된 리프레시 토큰 · 1회용 로그인 코드 정리 | 행이 계속 쌓임. 서버 cron 으로 정리 예정 |
| 6개월 지난 위치 이용 기록 정리 | 처리방침 · 위치 약관의 "6개월 보관". 위 cron 과 같이 `location_use_logs.created_at` 기준으로 지움 |
| 애플 로그인 회원 탈퇴 때 애플 토큰 철회 | App Store 심사 규정(5.1.1(v)) 상 탈퇴 시 애플 REST API 로 토큰을 철회해야 함. 애플 키(.p8) 와 인가 코드 교환이 필요 → 출시 전 탈퇴 API 보완 |
| 카카오톡 · 네이버 앱으로 간편 로그인 | 시스템 브라우저 창에서 카카오톡 · 네이버 앱 전환이 되는지 실기기 확인 필요. 안 되면 아이디 · 비밀번호 로그인만 |
| 인증 API 요청 횟수 제한 | 없음. 출시 전 검토 |
| 탈퇴 회원 개인정보 실제 삭제 배치 | 삭제 예정 시각만 기록. EC2 서버 cron 으로 돌릴 예정, 별도 작업 |
| 요원에게 실제 푸시 발송 (FCM) | 도착 알림은 알림 내역만 남김. Firebase 프로젝트 · 서비스 계정 키, 요원 앱 기기 토큰 등록 API 필요 |
| 카카오모빌리티 길찾기 무료 한도(하루 1만 건) 초과 대비 | 넘으면 그날 길찾기가 막혀 "도착 시간 미정". 하루 1만 건에 가까워지면 제휴 계약(건당 8원) |
| 업체 좌표 | 좌표가 비어 있으면 첫 도착 알림 때 주소로 찾아 저장(별도 스크립트 없음). 주소가 검색되지 않는 업체는 예상 시각이 계속 미정이라, 업체 등록 화면이 생기면 등록 때 좌표 확인 필요 |
| 진행 중인 발렛이 있으면 탈퇴 막기 | 발렛 세션 테이블(#9) 머지 후 추가 |
