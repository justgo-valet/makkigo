# 슬롯 이벤트 (기획 초안)

> 2026-11-26 초안. 화면 시안(A · B) 선택과 [출시 전 확인](#출시-전-확인)이 끝나면 구현합니다.
> 정한 이유는 [decisions.md](../decisions.md) 2026-11-26 줄.

회원이 발렛을 **N번 이용(출차 완료)할 때마다 슬롯을 1번** 돌릴 수 있습니다. 슬롯에서 슈퍼 어드민이 등록한 상품(치킨 기프티콘, 타이어 교체권 등)에 당첨될 수 있습니다. **당첨은 서버가 정하고**, 상품은 **운영팀이 직접 보냅니다**.

## 규칙

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 대상 | 회원만. 비회원 제외 | 기회 · 당첨을 묶을 계정과 연락처(휴대폰)가 필요 |
| 이벤트 단위 | **기간 한정**. 슈퍼 어드민이 시작 · 종료 시각, N, 대상 업체, 상품을 정함. 동시에 진행하는 이벤트는 하나. 시작 전 이용은 세지 않음(소급 없음). 남은 기회는 종료 때 사라짐 | 예산 · 기간 관리. 다음 달에 새 이벤트를 다시 열 수 있음 |
| 이용 세기 | 이벤트 기간 안에 출차 완료(`COMPLETED`, `completed_at` 기준)한 내 세션. **같은 업체는 하루(한국 시간 0시 기준) 1번만** 셈 — 셀 값 = (업체, 날짜) 쌍의 수 | 짧게 여러 번 맡기기, 요원과 짠 세션으로 부풀리기를 줄임. 다른 업체를 하루에 여러 곳 이용하는 일반 고객은 그대로 셈 |
| 기회 수 | `floor(센 이용 / N) − 돌린 횟수`. **저장하지 않고 매번 계산** | 세션 기록이 바뀌어도 어긋나지 않음 |
| 대상 업체 | 이벤트마다 **모든 업체** 또는 **고른 업체만**. 고른 업체만이면 화면에 대상 업체 목록 | 제휴 이벤트(예: 타이어 매장과 함께) |
| 상품 | 이벤트마다 **여러 개**. 상품마다 이름 · 사진 · 가액 · 총 수량 · 하루 수량(선택) · 당첨 확률 | 비싼 상품(타이어)을 낮은 확률로 섞을 수 있음 |
| 당첨 정하기 | 서버가 0 ~ 999,999 난수 하나로 상품 구간을 고름(확률 합 ≤ 100%). 고른 상품이 남아 있지 않으면(총 · 하루 수량) **꽝** — 다른 상품으로 넘기지 않음. 슬롯 1번에 상품 하나까지 | 화면에 공개한 확률과 실제가 같게. 화면에서 정하면 조작될 수 있음 |
| 한 번 더 | 가끔 "한 번 더" 그림 3개가 나오면 기회를 1번 더 줌(긁는 티켓안은 같은 티켓에 새 칸이 바로 다시 덮임). 확률은 이벤트마다 어드민이 정하고 수량 제한 없음. 상품 확률과 합쳐 100% 이하 | 재미가 끊기지 않게(사용자 요청). 상품 비용이 들지 않는 결과라 확률을 넉넉히 둘 수 있음 |
| 상품 소진 | 모든 상품이 다 나가면 돌리기를 막고 "상품이 모두 나갔어요" | |
| 지급 | **운영팀이 직접.** 앱은 "운영팀이 7일 안에 아래 번호로 연락드려요" 안내만. 실물(타이어 등)의 배송지 · 장착점도 운영팀이 연락해서 받음 | 외부 계약 없이 시작. 앱에 개인정보 수집 항목을 늘리지 않음 |
| 연락처 확인 | 휴대폰 번호는 **인증하지 않으므로** 당첨 안내 창에 번호 전체를 보여 주고 **내 번호가 맞아요 / 번호 바꾸기** 를 받음(바꾸기는 마이페이지 번호 수정과 같은 API). 확인한 시각을 당첨 기록에 남기고, 확인 없이 닫으면 내 당첨 내역에 "번호 확인 전" 으로 남아 다시 확인할 수 있음. 유의사항에도 "번호를 미리 확인해 주세요. 틀린 번호로 보낸 상품은 다시 보내 드리기 어려워요". 운영팀은 연락할 때 가입 차량 번호로 본인인지 한 번 더 확인(특히 고가 상품) | 오타 · 예전 번호면 상품이 남에게 감. 본인인증(PASS 등)은 비용 · 개발이 커서 이번엔 확인 단계로 대신. 돌리기 전이 아니라 당첨 때 물어 참여를 막지 않음 |
| 고가 상품 | 가액 **5만 원 초과** 상품은 유의사항 · 당첨 안내에 제세공과금(22%) 문구. 주민등록번호는 **앱에서 받지 않고** 운영팀이 따로 받음 | 기타소득 원천징수에 필요하지만 앱에 저장하면 보관 위험이 큼 |

C안은 이벤트 화면만 앱 색에서 벗어남. 고르면 [DESIGN.md](../../DESIGN.md) 에 이벤트 화면 범위를 더함.

## 긁는 티켓안 (D, 2026-11-27)

슬롯 대신 **발렛 티켓의 정해진 자리를 긁는** 방식. 고르면 위 규칙 중 "이용 세기 · 기회 수" 를 아래로 바꾸고, 나머지(상품 · 확률 · 수량 · 서버 결정 · 번호 확인 · 지급)는 그대로 씀.

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 자리 | 업체가 꾸민 티켓 위에 **마끼고가 정한 고정 자리**(세로 티켓은 아래쪽 약 38% 띠, 절취선 · 양옆 홈)에 긁는 칸 **3개**를 얹음. 티켓 디자인(`ticket_versions`)에는 저장하지 않고 화면에 그릴 때만 얹음. 업체 티켓 편집기에는 "이벤트 칸 자리" 안내선만 보여 줌 | 모든 업체 · 이미 발급된 티켓에 바로 적용, 업체 작업 없음. 발급된 티켓 디자인은 바꾸지 않는다는 규칙을 지킴 |
| 긁는 때 | **티켓을 받을 때(주차 완료)** 바로 | 기다리는 동안 긁는 재미, 티켓과 이벤트가 바로 이어짐 |
| 대상 티켓 | **모든 티켓**(회원 · 이벤트 기간 · 대상 업체). 같은 업체는 하루 1장만 | 매번 긁는 재미(사용자 결정). 비용은 확률 · 수량으로 관리 |
| 결과 | 처음 손대는 순간 서버가 결과를 정함. 같은 상품 그림 3개면 당첨, "한 번 더" 3개면 같은 티켓에 새 칸이 다시 덮임, 그 밖은 꽝. 각 칸은 절반쯤 긁으면 벗겨지고, 두 칸이 같으면 남은 칸이 달아오름. "한 번에 벗기기" 버튼도 둠 | 조작 방지, 손으로 긁기 어려운 사람 배려 |
| 안전장치 | 당첨은 주차 때 확인하지만 **상품은 그 발렛 이용이 출차 완료된 뒤** 보냄. 운영팀은 당첨자의 세션(부스 · 요원)을 같이 봄 | 모든 티켓이 대상이면 요원과 짠 가짜 주차로 긁는 칸을 늘리기 쉬움 |
| 진입 | 주차 완료 알림 · 홈 "발렛 티켓" 카드(긁지 않은 칸이 있으면 노란 "긁기" 표시, 높이 그대로) · 티켓 화면 | 홈에 줄을 늘리지 않음 |

- 데이터: `slot_spins` 대신 세션 단위 기록(예: `ticket_scratches` — 발렛 세션, 몇 번째 시도(한 번 더면 2, 3…), 결과, 당첨 상품, 번호 확인 시각, 지급 상태). `UNIQUE(valet_session_id, attempt)`.
- API(초안): `POST /api/v1/valet-sessions/{id}/scratch`(처음 긁을 때, 결과), 티켓 조회 API 에 긁는 칸 상태를 더함.
- 구현: 긁는 칸은 `TicketRenderer` 위에 얹는 별도 컴포넌트(canvas, 새 의존성 없음). 비회원 티켓 이미지 저장에는 들어가지 않게.

## 슈퍼 어드민 (`apps/admin`)

- **이벤트**: 목록 · 만들기 · 고치기 — 이름, 기간, N, 대상 업체, 상품. 시작한 뒤에는 N · 대상 업체 · 확률을 바꾸지 못하고 수량만 늘릴 수 있음(참여 중인 회원에게 공정하게). 가액 5만 원 초과 상품은 제세공과금 경고.
- **상품 사진**: 업체 사진과 같은 방식(`staging` → 완료 때 검사 · 복사).
- **당첨자**: 이벤트별 목록(당첨 시각 · 상품 · 회원 휴대폰 · **번호 확인 여부** · 상태 · 메모). 상태는 연락 대기 → 보냄 / 연락 안 됨 / 취소.
- **현황**: 참여 회원 수, 돌린 횟수, 상품별 남은 수량.

## 데이터 · API (초안)

| 테이블 | 내용 |
|---|---|
| `slot_events` | 이름, `starts_at` · `ends_at`, `uses_per_spin`(N), `merchant_scope`(`ALL` · `SELECTED`), "한 번 더" 확률(`retry_probability_ppm`), 만든 어드민, 삭제 표시 |
| `slot_event_merchants` | 이벤트 ↔ 업체(`SELECTED` 일 때) |
| `slot_event_prizes` | 이름, 사진 키, 가액(원), 총 수량, 하루 수량(없으면 제한 없음), 확률(`probability_ppm`, 1,000,000 = 100%), 순서 |
| `slot_spins` | 이벤트, 회원, `spin_number`(그 회원의 몇 번째), 당첨 상품(꽝이면 비움), 시각, 번호 확인 시각(`phone_confirmed_at`), 지급 상태 · 처리 어드민 · 메모. `UNIQUE(event_id, user_id, spin_number)` 로 두 번 눌러도 한 번만 |

- 수량 초과 방지: 돌릴 때 트랜잭션에서 상품 행을 `FOR UPDATE` 로 잠그고 당첨 수를 세서 확인.
- 당첨자 휴대폰은 `users` 에서 읽음(복사해 두지 않음).
- 고객 API: `GET /api/v1/slot-events/current`(이벤트 · 상품 · 내 기회), `POST /api/v1/slot-events/{id}/spins`(결과 · 남은 기회, 409 `NO_SPIN_LEFT` · `EVENT_ENDED` · `SOLD_OUT`), `GET /api/v1/slot-events/{id}/spins/me`(내 당첨 내역), `POST /api/v1/slot-events/{id}/spins/{spinId}/phone-confirmation`(번호 확인, 204). 번호 바꾸기는 기존 `PATCH /api/v1/users/me/phone-number`.
- 요원 앱 출차 완료 처리 뒤: 기회가 새로 생긴 동의 회원에게 푸시.

## 열린 질문

- 시안 A · B 선택(대표님).
- 첫 이벤트 값: 기간, N, 상품 · 수량 · 확률.
- 홈 진입: 마이페이지 아이콘 밑 알약 버튼(권장)과 반 칸 카드 중 하나. 알약은 업체 이름이 길면 이름이 더 일찍 말줄임됨.
- 업체 없이 주차한 세션(`merchant_id` 없음)도 셀지. 센다면 하루 1번.
- 당첨 뒤 연락이 닿지 않을 때 기한과 당첨 취소 여부, 발송 전 탈퇴하면 당첨 취소인지.
- 슬롯(A · B · C)과 긁는 티켓(D) 중 무엇으로 갈지.
- 긁는 티켓: 비회원 티켓에도 칸을 보여 주고 "회원이면 긁을 수 있어요" 로 가입을 권할지. 가로 티켓(`STUB_NOTCHES`, 7:5)에서 긁는 칸 자리. 이미 발급된 티켓에서 업체 글자가 아래쪽 띠에 있으면 가려짐(안내선은 새 디자인부터).
- 휴대폰 본인인증(PASS 등)을 둘지. 지금은 당첨 때 번호 확인으로 대신함. 고가 상품만이라도 인증 뒤 지급할지([open-questions.md](open-questions.md) 의 알림톡 · 번호 인증 항목과 같이 정함).
