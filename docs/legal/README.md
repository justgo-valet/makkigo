## 작성 원칙 — 약관 개정을 줄이기 위해

- 약관에는 **기능 · 화면 · 요금 계산 방식 · 상태 이름**을 적지 않습니다. "회사가 정하는 서비스", "서비스 화면의 안내" 로 받습니다. 기능이 바뀌어도 약관은 그대로입니다.
- 연락처처럼 자주 바뀌는 값은 약관에 넣지 않고 처리방침 · 서비스 화면에 둡니다. 다만 법이 약관에 요구하는 사업자 전화번호 · 전자우편은 사업자 정보에 적습니다.
- 개인정보 문서는 법상 항목 · 목적 · 기간을 적어야 해서 **항목을 묶어서**(예: "서비스 이용 기록") 적습니다. 새 컬럼이 생겨도 같은 묶음이면 다시 동의받지 않아도 됩니다.
- 다시 동의가 필요한 것: 새 목적, 새 묶음의 항목, 새 제3자. 공지만 필요한 것: 처리방침의 수탁자 · 보관 기간 변경.
- 문서에 적는 수집 항목 · 보관 기간 · 안전조치는 **실제 코드 · 운영과 같아야** 합니다. 수집하지 않는 것을 적지 않고, 적은 것은 구현합니다.

**변호사 검토 때 물을 것**
- 위치정보사업 허가 · 등록이 따로 필요한지. 기기 OS 가 준 좌표를 받아 우리 서비스에만 쓰는 경우라 위치기반서비스사업 신고만으로 되는지
- 요원(발렛 사업자)에게 **좌표가 아닌 예상 도착 시각**만 보여주는 것이 개인위치정보 제3자 제공(제19조 제2항 · 제3항, 제공 때마다 이용자에게 통보)에 해당하는지. 가공값이라 아니라고 보지만, 보수적으로 도착 알림 완료 문구에 "요원에게 예상 도착 시각을 알렸어요" 를 넣는 방안
- 길찾기 API 제공사(카카오모빌리티)에 출발 · 도착 좌표를 보내는 것을 처리 위탁으로 볼 수 있는지
- 확인자료 보관 기간(초안 6개월)
- 이용약관 제6조에서 "통신판매중개자" 를 뺀 입장이 맞는지

## 개발 · 운영에서 지킬 것 (정보보안)

- **고객 휴대폰 번호는 요원 앱 API 응답에 넣지 않습니다.** 제3자 제공 동의서가 "제공하지 않음" 으로 약속합니다.
- 푸시 내용에 휴대폰 번호 등을 넣지 않습니다 (잠금 화면 · 국외 이전 최소화).
- **고객 좌표는 DB · 로그 · 오류 추적에 남기지 않습니다.** 위치기반서비스 동의가 없으면 앱에 위치를 요청하지도, 서버가 좌표를 쓰지도 않습니다.
- 탈퇴 회원의 휴대폰 번호 · 차량 정보 · 고객 알림 내역은 탈퇴 30일 뒤 정기 작업이 지웁니다 → [runbook.md](../operations/runbook.md#정기-정리-작업). 운영 SSM 에 `USERS_INTERNAL_JOB_TOKEN` 이 있어야 돕니다.
- 접속 기록(IP)은 수집하지 않습니다. Caddy 접속 로그를 켜게 되면 처리방침 1 · 2 절에 항목과 보관 기간을 다시 넣습니다.
- 운영 DB 직접 접속 기록을 1년 이상 남기고 점검합니다 (위 할 일 표, 미설정). DB 백업에도 같은 보관 기간을 적용합니다.
- 처리방침 공개 주소 `https://app.makkigo.com/privacy` (로그인 없이 열림)를 두 스토어에 등록합니다. 이용약관 주소는 `https://app.makkigo.com/terms` 입니다. App Store 개인정보 라벨 · Play 데이터 보안 양식을 처리방침과 맞춥니다.
- 비회원 QR 화면에 차량 번호 제공 동의와 "개인정보 처리방침" 링크를 둡니다 (위 할 일 표).
