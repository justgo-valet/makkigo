## 작성 원칙 — 약관 개정을 줄이기 위해

- 약관에는 **기능 · 화면 · 요금 계산 방식 · 상태 이름**을 적지 않습니다. "회사가 정하는 서비스", "서비스 화면의 안내" 로 받습니다. 기능이 바뀌어도 약관은 그대로입니다.
- 연락처처럼 자주 바뀌는 값은 약관에 넣지 않고 처리방침 · 서비스 화면에 둡니다.
- 개인정보 문서는 법상 항목 · 목적 · 기간을 적어야 해서 **항목을 묶어서**(예: "서비스 이용 기록") 적습니다. 새 컬럼이 생겨도 같은 묶음이면 다시 동의받지 않아도 됩니다.
- 다시 동의가 필요한 것: 새 목적, 새 묶음의 항목, 새 제3자. 공지만 필요한 것: 처리방침의 수탁자 · 보관 기간 변경.

## 검토 결과와 반영

카카오 T(중개 플랫폼) · 아이파킹(주차 · 발렛) 약관 · 처리방침, 「개인정보 보호법」(2023 개정) · 전자상거래법 · 약관규제법 기준.

| 항목 | 결정 | 근거 |
|---|---|---|
| 제3자 제공 | **필수 동의 추가** | 발렛 부스는 별도 사업자라 위탁이 아닌 제3자 제공. 개정법 제17조 제1항 제2호는 계약 이행을 제공 근거에서 뺌 |
| 국외 이전 | **동의 항목에서 뺌, 처리방침 5절에 공개** | 계약 이행용 처리위탁은 처리방침 공개로 갈음 (제28조의8 제1항 제3호). 데이터는 AWS 서울 리전이라 국외로 가는 건 푸시(FCM · APNs)뿐 |
| 만 14세 | **필수 확인 추가** | 14세 미만 개인정보는 법정대리인 동의 필요 (제22조의2) |
| 요금 분쟁 | 발렛 사업자 책임, 회사는 중개자(거래 당사자 아님) | 전자상거래법 제20조 중개자 고지. 단 회사 고의 · 중과실 면책은 무효(약관규제법 제7조)라 그 부분은 남김 |
| 보관 기간 | 이용 기록 5년, 접속 기록 3개월, 탈퇴 후 개인정보 30일 | 전자상거래법 · 통신비밀보호법, 아이파킹도 5년 |
| 알림톡 수탁자 | 카카오 + 대행사 | 카카오가 휴대폰 번호를 처리 |
| 카카오톡 미사용자 | 문자로 대체하지 않음 | 푸시 → 알림톡 정책 유지, 문자 대행사 추가 불필요 |

## 위치정보

도착 알림을 보낼 때 고객의 현재 위치를 **한 번** 받아 업체까지의 예상 도착 시각을 계산합니다 → [policies.md](../planning/policies.md#위치정보). 그래서 「위치정보의 보호 및 이용 등에 관한 법률」(위치정보법)을 지켜야 합니다.

| 할 일 | 하는 곳 | 상태 |
|---|---|---|
| 위치기반서비스사업 신고 (방송통신위원회, 제9조) | 회사 | 미정 — 처리 기간을 확인해 출시일(10/31) 전에 끝나는지 봐야 함 |
| 위치정보관리책임자 지정 | 회사 | 빈칸 |
| 위치기반서비스 이용약관 명시 · 동의 (제18조) | 코드 | 온보딩 약관 시트 · 도착 알림 위치 동의 시트, 선택 동의 ([본문](../../apps/users/features/consent/documents/locationBasedService.ts)) |
| 수집 · 이용 · 제공 사실 확인자료 자동 기록 · 보존 (제16조 제2항) | 코드 | 위치 이용 기록 테이블. 좌표는 남기지 않음 |
| 목적 달성 후 개인위치정보 파기 | 코드 | 좌표는 계산에만 쓰고 저장하지 않음 |
| 동의 철회 시 확인자료 파기 (제24조 제4항) | 코드 | 위치기반서비스 미동의를 기록하거나 탈퇴하면 그 회원의 위치 이용 기록을 바로 지움 |
| 확인자료 6개월 지나면 정리 | 코드 | 미정 — 서버 cron 작업과 함께 ([open-questions.md](../planning/open-questions.md)) |
| 처리방침에 위치정보 · 길찾기 API 제공사(카카오모빌리티) 반영 | 문서 | [privacy-policy.md](privacy-policy.md) |

**변호사 검토 때 물을 것**
- 위치정보사업 허가 · 등록이 따로 필요한지. 기기 OS 가 준 좌표를 받아 우리 서비스에만 쓰는 경우라 위치기반서비스사업 신고만으로 되는지
- 요원(발렛 사업자)에게 **좌표가 아닌 예상 도착 시각**만 보여주는 것이 개인위치정보 제3자 제공(제19조, 제공 때마다 이용자에게 알림)에 해당하는지
- 길찾기 API 제공사(카카오모빌리티)에 출발 · 도착 좌표를 보내는 것을 처리 위탁으로 볼 수 있는지
- 확인자료 보관 기간(초안 6개월)

## 개발 · 운영에서 지킬 것 (정보보안)

- **고객 휴대폰 번호는 요원 앱 API 응답에 넣지 않습니다.** 제3자 제공 동의서가 "제공하지 않음" 으로 약속합니다.
- 푸시 내용에 휴대폰 번호 등을 넣지 않습니다 (잠금 화면 · 국외 이전 최소화).
- **고객 좌표는 DB · 로그 · 오류 추적에 남기지 않습니다.** 위치기반서비스 동의가 없으면 앱에 위치를 요청하지도, 서버가 좌표를 쓰지도 않습니다.
- 탈퇴 회원 삭제 배치가 없으면 처리방침의 "30일" 을 지키지 못합니다. **출시 전 필수.**
- 운영 DB 직접 접속 기록을 1년 이상 남기고 점검합니다. DB 백업에도 같은 보관 기간을 적용합니다.
- 처리방침 공개 주소(`app.makkigo.com/privacy`)가 스토어 등록에 필요합니다. App Store 개인정보 라벨 · Play 데이터 보안 양식을 처리방침과 맞춥니다.
- 비회원 QR 화면에 "입력한 차량 번호는 요청 처리에만 쓰입니다 · 개인정보 처리방침" 링크를 둡니다.
